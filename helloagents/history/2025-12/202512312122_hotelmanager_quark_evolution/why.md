# 变更提案: HotelManager 深度递归进化（Quark-Level Evolution）

## 需求背景
仓库已具备可运行、可测试的酒店管理骨架（CLI + SQLite）与静态管理台 UI。当前痛点是：UI 与真实数据缺乏联通、CLI 文件复杂度偏高、SQL 片段拼装分散导致审计成本上升。

## 产品分析

### 目标用户与场景
- **用户群体:** 酒店运营人员（店长/前台/收益经理）、开发者（需要可脚本化能力）
- **使用场景:** 本地/离线操作房态与预订；导出数据；用可视化面板快速定位重点

### 价值主张与成功指标
- **价值主张:** 零依赖、离线可用、可审计的酒店管理引擎 + 可导入真实数据的静态管理台
- **成功指标:**
  - CI/测试全绿
  - `export snapshot` 输出 schema 稳定且可被 Web UI 成功导入
  - CLI 可维护性提升（命令模块化，边界清晰）

## 变更内容
1. 新增 JSON 快照导出（`export snapshot`）
2. Web UI 支持导入快照并刷新 KPI/预订列表
3. CLI 模块化重构与输出工具收敛
4. Repository/DB 安全与可审计性加强（受控 SQL 片段、表名白名单）

## 核心场景

### 需求: 数据快照导出与导入
**模块:** CLI / Web UI

#### 场景: 导出快照
用户执行命令生成 `snapshot.json`。
- 输出包含：`stats` / `rooms` / `guests` / `bookings` / `schema_version`

#### 场景: Web UI 导入
用户在浏览器打开 `web/index.html`，拖拽或点击上传导入 `snapshot.json`。
- KPI 与“最新预订节拍”刷新
- 格式不匹配时给出明确错误提示
