# 30 次迭代：夸克级审查与升级清单

> 目标：把 HotelManager 打磨成“可长期演进的专业级骨架”（稳定、可测试、可 CI、可迁移、可扩展）。
>
> 说明：
> - 本清单用于追踪“30 次迭代”的交付粒度（每一项都应对应一个独立、可回滚的原子提交）。
> - 每项迭代完成后，应保证 `python -m compileall` 与 `unittest` 通过。

## 迭代 01-10：核心质量与安全

- [x] 01. 增加数据库 `doctor` 信息：schema 版本、journal_mode、foreign_keys 等
- [x] 02. 为 WAL 启用失败提供可行动错误提示（而非静默降级）
- [x] 03. 引入统一事务工具（commit/rollback 一处管理）
- [x] 04. 预订创建改为“同事务内冲突检测 + 写入”（避免并发双订）
- [x] 05. 覆盖 DB 迁移测试：从旧 schema 升级到新 schema
- [x] 06. 数据一致性校验：关键表/列缺失时输出友好报错
- [x] 07. 改善邮箱校验：更明确、可定位的错误信息
- [x] 08. 改善金额处理：增强边界条件与错误信息
- [x] 09. 统一时间戳策略：明确 UTC 写入与展示约定
- [x] 10. 增加异常分层：为常见 sqlite3 异常映射为可预期错误

## 迭代 11-20：功能扩展与体验

- [x] 11. 预订支持改期（reschedule）：同样做冲突检测与事务保护
- [x] 12. CLI：新增 `booking reschedule` 命令
- [x] 13. 预订支持延住（extend）：仅修改 end_date
- [x] 14. CLI：新增 `booking extend` 命令
- [x] 15. 预订列表支持日期过滤（按 start/end 区间）
- [x] 16. CLI：新增 `stats revenue`（按日期统计收入：房价快照 * 晚数）
- [x] 17. 房间支持按条件检索（容量/房型/状态组合）
- [x] 18. CLI：输出支持 `--json`（便于脚本化）
- [x] 19. 导出能力：rooms/guests/bookings 导出 CSV
- [x] 20. 示例脚本：提供可复现实例（Windows + *nix）
